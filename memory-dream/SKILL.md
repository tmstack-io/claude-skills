# memory dream（記憶の横断整理）

Claude Code の記憶階層（全プロジェクトの auto-memory）のうち、**ネイティブ auto-dream が扱わない範囲**を整理する作業の手順書。

## ネイティブ auto-dream との役割分担

**ネイティブが担う範囲**: Claude Code 本体の auto-dream は、プロジェクト単位で「24 時間経過かつ 5 セッション以上」を条件に自動発火し（`/dream` で手動実行も可）、transcript を読んで記憶のマージ・矛盾エントリの削除・相対日付の絶対化・MEMORY.md の索引トリムをバックグラウンドで行う — プロジェクト内の日常的な consolidation はこちらに任せる。

**本スキルが補完する範囲**: ネイティブが行わない、全プロジェクト横断の一括整理・実行前フルバックアップと採用前レビュー・上位レイヤ（CLAUDE.md / rules）との重複排除・実リポジトリとの突合検証・グローバル昇格候補の報告。

## 対象（Claude Code の記憶階層）

dream が編集するのは **auto-memory 全体**:

- `~/.claude/projects/<project-slug>/memory/` — プロジェクトごとの auto-memory
  - `MEMORY.md` — 索引（毎セッション自動ロード。1 ファイル 1 行フック）
  - `*.md` — 個別メモリ（frontmatter 付き。関連時に想起）

省略時は memory/ を持つ全プロジェクトを列挙して順に処理する:

```bash
ls -d ~/.claude/projects/*/memory 2>/dev/null
```

上位レイヤは **参照のみ**（ルールの定義元として重複判定に使う。dream では編集しない）:

1. `~/.claude/CLAUDE.md`・`~/.claude/rules/*.md` — ユーザーグローバル指示（最上位・ユーザー手動管理）
2. 各リポジトリの `CLAUDE.md`・`.claude/rules/`・`AGENTS.md` — プロジェクト指示（リポジトリ管理）

### 引数の解決（slug / リポジトリパス ⇄ 実リポジトリ）

「存在しないファイル/シンボル参照の除去」には実リポジトリのパスが要る。slug の機械的復元は一意でない（`/` も `.` も `-` に潰れる）ため、セッション記録の cwd を正とする:

- **slug → リポジトリパス**: 対象 slug の transcript から cwd を取る。

  ```bash
  grep -hm1 -o '"cwd":"[^"]*"' ~/.claude/projects/<slug>/*.jsonl 2>/dev/null | head -1
  ```

- **リポジトリパス → slug**（引数がパスの場合）: 全 slug の transcript から cwd を取り出し、指定パスと一致する slug を選ぶ。複数一致した場合は候補を散文提示で確認する。一致ゼロの場合（transcript 削除済み・パス表記の揺れ等）は編集に入らず、指定パスと cwd が近い候補 slug の一覧を散文提示して指示を待つ。

  ```bash
  for d in ~/.claude/projects/*/; do
      cwd=$(grep -hm1 -o '"cwd":"[^"]*"' "$d"*.jsonl 2>/dev/null | head -1 | sed 's/"cwd":"//;s/"$//')
      [ "$cwd" = "<指定パス>" ] && basename "$d"
  done
  ```

リポジトリが手元に無い（削除済み・別マシン）場合、その memory の実体検証は**検証不能**とする — 削除せず保持し、その旨を報告する。検証の基準は常に**対象プロジェクトのリポジトリ・上位レイヤ**であり、現在開いているプロジェクトではない。

## 実施モデル（非破壊・レビュー後採用）

auto-memory は git 管理外のため、「入力非破壊・レビュー後採用」は**実行前フルバックアップ＋変更内容の明示報告＋採用確認**で実現する。バックアップ取得前に memory を編集しない。実行前に必ず取得し、検証する:

```bash
BK=~/.claude/backups/memory-dream-$(date +%Y%m%d-%H%M%S)
mkdir -p "$BK"
fail=0
for d in ~/.claude/projects/*/memory; do
    slug=$(basename "$(dirname "$d")")
    cp -a "$d" "$BK/$slug" || { echo "COPY-FAIL $slug"; fail=1; continue; }
    src=$(find "$d" -type f | wc -l); dst=$(find "$BK/$slug" -type f | wc -l)
    [ "$src" -eq "$dst" ] || { echo "COUNT-MISMATCH $slug ($src -> $dst)"; fail=1; }
done
[ "$fail" -eq 0 ] && echo "BACKUP-OK $BK" || echo "BACKUP-NG"
```

引数でプロジェクトが指定された場合は、`for` の対象を `~/.claude/projects/<slug>/memory` の 1 件に置き換えて同じ検証を行う。出力が `BACKUP-OK` でなければ**編集に入らず中止**し、失敗した対象と原因（`COPY-FAIL` / `COUNT-MISMATCH` の行）を報告する。`BACKUP-OK` 行に出力された絶対パスを控え、以降の復元コマンド・`progress.md` への追記・報告では `$BK` を**展開済みの実際の絶対パス**で書く（Bash 実行は呼び出しごとに新しいシェルで走り、変数は持続しない）。

復元は「現在の memory を退避してから戻す」形で行う（報告にもこの形で載せる）。復元はバックアップ取得時刻の状態へ戻す操作であり、取得以降にネイティブ auto-dream が加えた変更も巻き戻る:

```bash
mv ~/.claude/projects/<slug>/memory ~/.claude/projects/<slug>/memory.pre-restore-$(date +%Y%m%d-%H%M%S) \
  && cp -a "$BK/<slug>" ~/.claude/projects/<slug>/memory
```

**中断への備え**: 1 プロジェクトの処理を終えるごとに、その slug と結果（削除・統合・再編・保留・検証不能の件数）を `"$BK/progress.md"` へ追記する。セッションが途中で切れた場合は、`~/.claude/backups/memory-dream-*` のうち最新のものを候補として散文提示で確認してから引き継ぎ、その `progress.md` に載っている slug を処理済みとして残りから再開する。

## 4 フェーズ手順（プロジェクトごとに独立して実施）

1. **Mine（採掘）**: 対象プロジェクトの transcript（`~/.claude/projects/<slug>/*.jsonl`、更新日時の新しい順に**直近 20 セッションまで**）を走査する。全文は読了せず、`jq` / `grep` でユーザー発話とアシスタントの結論に相当する行へ絞ってから読み、1 セッションあたり要点 **5 件まで**を抽出する。抽出物は「候補 × 出現セッション数」の表に集約し、**2 セッション以上で出現した**指摘・確定した方針・新事実だけを抽出候補とする（transcript が 2 セッション以下のプロジェクトでは閾値を 1 セッションに下げる）。一回限りのデバッグメモは拾わない。閾値で落とした候補の件数は報告に載せる。
   完了条件: 対象範囲の全 transcript を走査し終え、出現セッション数つきの抽出候補一覧（閾値で落とした件数を含む）が手元にある。
2. **Consolidate（統合）**: 抽出候補を既存記憶へマージする。ネイティブ auto-dream が既に処理する領域（相対日付の絶対化・記憶内矛盾の最新値での解決）は、活動の少ないプロジェクトで**未処理のまま残っている分だけ**行う。実リポジトリと突合し、存在しないファイル/関数/フラグを指す記述は除去（or 現存確認して更新）。plan・進行中タスクのメモリは実際の進捗を確認し、完了していれば恒久知見へ再編する。対象リポジトリへの操作は**読み取りのみ**とし、作業ツリーとブランチの状態を変える操作は行わない。マージ状態は `git log` / `git branch --contains` で判定し、PR 状態は `gh` が使える場合のみ参照する（`gh` が使えない場合、および対象が git 管理下でない場合は、判定不能としてメモリを保持したまま報告する）。
   完了条件: 抽出候補の全件がマージ・破棄のいずれかに振り分けられ、記憶内の全ファイルについて日付・矛盾・実在参照の点検を終えている（リポジトリ不在分は検証不能として保持・報告）。
3. **Dedup & Resolve（重複排除・矛盾解消）**: 階層をまたいだ重複を除去する。**最重要原則: 上位レイヤが定めるルールを下位で再掲しない。** 重複の扱いは「重複排除の判定ルール」に従い、そのプロジェクト固有の知見だけを残す（残し方は「成果ファイルの書き方」に従う）。上位と下位に真の矛盾がある場合は散文提示で確認する。
   完了条件: 記憶内の全ファイルを上位レイヤと照合し終え、重複ゼロ。真の矛盾は散文提示で決着済みか、報告の保留一覧に載っている。
4. **Prune & Index（剪定・索引化）**: `MEMORY.md` を lean な索引に保つ（1 ファイル 1 行フック、目安 200 行未満）。索引トリムはネイティブ auto-dream の担当領域のため、Phase 2 と同様に**未処理のまま残っている分だけ**行う。冗長な節・完了済みで価値の無い記述を削除する。ファイルの新設・改名・削除をしたら索引と `[[リンク]]` を同期し、整合を検証する:

   ```bash
   MEM=~/.claude/projects/<slug>/memory
   # 索引 → 実ファイル
   grep -o '([a-z0-9-]*\.md)' "$MEM/MEMORY.md" | tr -d '()' | while read -r f; do [ -f "$MEM/$f" ] || echo "MISSING $f"; done
   # 実ファイル → 索引
   for f in "$MEM"/*.md; do b=$(basename "$f"); [ "$b" = MEMORY.md ] && continue; grep -q "($b)" "$MEM/MEMORY.md" || echo "UNINDEXED $b"; done
   # [[リンク]] の dangling（コードブロック内の TOML `[[...]]` 等は誤検出しうる — 目視で除外）
   grep -ho '\[\[[a-z0-9-]*\]\]' "$MEM"/*.md | sort -u | tr -d '[]' | while read -r n; do [ -f "$MEM/$n.md" ] || echo "DANGLING [[$n]]"; done
   ```

   完了条件: 検証コマンドの `MISSING` / `UNINDEXED` / `DANGLING` の出力がゼロ、または残った各行について出典ファイル名と該当行を報告に列挙し、コードブロック内の誤検出である根拠を添えている。

### 並列化（サブエージェント委任）

プロジェクト間は独立なので、多数のプロジェクトを対象とする場合は**1 プロジェクト 1 サブエージェント**を単位として調査・検証を委任してよい。サブエージェントは読み取りと報告のみを行い、`~/.claude/projects/` 配下への書き込みは本体だけが行う。編集の採用判断と最終レビューも本体で行う。

- **渡すもの**: 対象 slug、特定済みリポジトリパス（不在ならその旨）、検証項目（実在参照の確認・plan の進捗確認・上位レイヤとの重複候補の列挙）
- **返させるもの**: 実在しないファイル/シンボル参照の一覧、plan ごとの完了判定と根拠、削除・統合の提案一覧（ファイル名と理由）、検証不能とした対象とその理由

完了条件: 委任した全プロジェクトから上記形式の返却が揃っている（揃わない分は本体が自己実行する）。

## 重複排除の判定ルール

- 重複は常に「下位（auto-memory）→ 上位（CLAUDE.md / rules）」方向で発生する。**修正は auto-memory 側**で行い、上位（ユーザー・リポジトリ管理物）は触らない。
- 各情報は定義箇所を一つに保つ。上位が定めるルールは auto-memory から黙って削除する — 「黙って」は記憶ファイル本文に削除の痕跡やメタ注記を残さないという意味であり、削除は報告に必ず件数と内訳を載せる。必要なら所在だけを 1 句で指す — その際は**実在を確認したパスのみ**を書く。
- リポジトリ自身が記録している事実（コード構造・過去の修正・git 履歴・CLAUDE.md 記載事項）は auto-memory から削除する。
- 同種の知見が複数プロジェクトの auto-memory に現れる場合、それはプロジェクト非依存の候補である。報告のグローバル昇格候補に載せ、散文提示でユーザーの承認を得てから `~/.claude/CLAUDE.md` へ反映する。

### 成果ファイルの書き方（重要）

auto-memory の形式規約（frontmatter の `name`/`description`/`metadata.type`、feedback/project タイプの **Why:** / **How to apply:**）は維持する。そのうえで:

- **Why:** は行動を変える技術的因果に限定する（「A だと B が壊れるので C する」）。
- 本文は残す知見だけで構成する（重複の扱いは「重複排除の判定ルール」に従う）。
- dream が新設するファイルの frontmatter は形式規約の項目のみで構成する。既存ファイルの自動付与メタデータ（`originSessionId` 等）はそのまま保持する。
- 陳腐化した plan は、完了後も価値の残る恒久知見（確定した仕様・残存バグ・環境の落とし穴）へ再編して残す。価値が残らなければファイルごと削除する。

## 報告とレビュー（採用ゲート）

全プロジェクトの処理後（または中断時）、次の内容を**応答本文に散文提示の一覧形式**で報告する（最終報告の本文はファイルに保存しない。進捗記録 `"$BK/progress.md"` は「実施モデル」に従い保存する）:

- バックアップ先の絶対パス・取得時刻・復元コマンド（「実施モデル」の退避つき復元の形で載せる）、および既存の `memory-dream-*` バックアップの個数
- プロジェクトごとの結果ブロック: 削除・統合・再編・保留（真の矛盾等）・検証不能の各件数と内訳（ファイル名と一言の理由）
- グローバル昇格の候補一覧（あれば）
- 中断した場合: 処理済み slug と未処理 slug の一覧

報告の末尾で「このまま採用する」「指定プロジェクトのみバックアップから復元する」「全プロジェクトをバックアップから復元する」を散文提示で確認する。dream の出力には hallucination が混入しうるため、この採用確認を経ずに完了としない。採用後もバックアップは削除せず残す（不要になったバックアップの削除は利用者が手動で行う）。

完了条件: 報告の全項目（該当なしはその旨）を提示し、ユーザーの採用・復元の回答を得ている。
