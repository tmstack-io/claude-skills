# 選択肢の提示を散文提示に統一し選択式 UI ツールを使わない

査読・選別・承認を持つスキル（skill-refine 等）で、選択式 UI ツール（AskUserQuestion）による確認は、ツールが呼ばれず選択肢が提示されないままターンが終わる機能漏れを実運用で繰り返し起こした。またラベル数語に圧縮された選択肢文面は、内容の吟味を要する選択（指摘の採否等）で読者に内容を正しく理解させられなかった。そこで全スキル共通の設計規約として、ユーザーへの選択・承認・確認は応答本文の散文（空行区切り・番号または見出し・推奨明示、読者想定と用語の規定つき）で提示しテキスト回答を待つ「散文提示」に統一し、選択式 UI ツールの使用を廃止した。文面要件の正本は CLAUDE.md のスキル設計規約。

## Considered Options

- **内容吟味型の選択のみ散文化し、軽量確認（続行可否の二択等）は選択式 UI を維持する案**: 線引き自体が曖昧な判断ゲートになり（規約の二値化原則に反する）、機能漏れは軽量確認でも起こるため却下。

## Consequences

- 執行機構は agent-skills の skill-refine 査読基準（基準 D にモード非依存の査読項目として追加済み。`--myself` 査読でも効く）。既存スキルの選択式 UI 規定（iterate-review / pr-comment / pr-recheck / roundtable）は次回の `/skill-refine --myself` 査読で指摘され、承認を経て散文提示へ移行する（遅延適用）。
- 同内容の決定は agent-skills リポジトリの docs/adr/0002 にも記録している（規約の正本が各リポジトリにあるため、ADR も各リポジトリが自前で持つ）。
