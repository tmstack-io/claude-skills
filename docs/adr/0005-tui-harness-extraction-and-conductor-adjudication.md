# TUI 基盤を tui-harness スキルへ切り出し、承認ダイアログは指揮者裁定に統一する

Status: accepted

roundtable の TUI 専用化で実装した基盤（mux.sh・tui-protocol.md・ハーネス別 transports・カタログ）が、concertino の汎用化（配役先を codex 固定から任意ハーネスへ）でも必要になり、スキルごとの二重定義が始まる状態になった。基盤一式を独立スキル `tui-harness`（モデル起動型）へ切り出し、mux.sh（マルチプレクサラッパー）・catalog.sh（ハーネスの疎通確認とモデル一覧）・transports/（ハーネス別差分）・共通手順（起動・委譲・受理判定・pull 安全網・クローズ）の正本とする。利用スキル（roundtable / concertino / solista）は SKILL.md を Read して同一コンテキストで適用し、呼び出し固有の値（成果物置き場・push ラベル・裁定スコープ）をパラメータとして与える。基盤層の語彙は「ハーネス」に中立化し、「奏者」「賢者」は各利用スキルのロール名として再定義する（旧 tui-transport の読み替え表方式は廃止）。

あわせて、書き込みを伴う配役の承認は**指揮者裁定**に統一する: ハーネスの承認ダイアログは pull 安全網の blocked 発火で検知し、呼び出し側が委譲時に定めた**裁定スコープ**（許可する書き込み先・許可するコマンド）との照合で二値裁定する。ハーネスの承認機構の差（自動裁定あり / 選択的承認 / 毎回承認）による配役制限は設けない。未知の承認ダイアログに遭遇した場合は、スコープで判定可能ならその場で裁定して実測を記録し、判定不能ならユーザーに確認する — いずれもセッション末尾に transports への追記案を提示し、承認を得てから正本へ反映する（無承認の自己改定はしない）。

## Considered Options

- **基盤を各スキル内に保持（現状維持）** — 却下。concertino 汎用化の時点でハーネス知識（起動・trust・承認ダイアログ・実測記録）が2スキルに複製され、実測知見の反映先が割れる。
- **共通原則のみ切り出し、transports・カタログは各スキルに残す** — 却下。ハーネス知識こそ重複の本体であり、原則だけの共有では利用スキルが増えるたびに transports が分岐する。
- **implement 配役を自動裁定機構を持つハーネス（codex / cursor-agent）に限定する適性制限** — 却下。機械的な二値判定にはなるが、agy / grok の実運用で確立した「blocked 検知 → 議長裁定」がそのまま指揮者裁定として一般化でき、制限なしでも安全に運用できる。ダイアログ頻発のコストは注記に留め、選択の自由を優先する。
- **未知ダイアログでの自動自己改定（無承認で transports を書き換える）** — 却下。一度の誤解釈が正本に固定化され全セッションへ伝播する・並行セッションの書き換え競合・「カタログ追記は承認を得てから」という既存規約との不整合のため、承認ゲート付きの追記案提示に留める。
- **基盤切り出し＋指揮者裁定＋承認付き自己改定（採用）**。

## Consequences

- tui-harness が TUI 運用知識の単一正本になり、新ハーネス対応は「catalog.sh に probe / models 分岐＋実測検証＋transports 追加」、新マルチプレクサ対応は「mux.sh にバックエンド追加」という増分作業に限定される。
- roundtable / concertino / solista は自スキルのプロトコル（合議 / 配役）だけを持つ薄い構成になる。concertino-codex の tui-transport.md / cli-transport.md は消滅し、リポジトリは TUI 専用で統一される（非 TUI 環境では各スキルが入口ゲートで中止）。
- concertino-codex / solista-codex は `concertino` / `solista` に改名される（codex 固定の印を外す。旧名のエイリアスは置かないクリーンブレーク）。`~/.claude/skills/` のシンボリックリンク張り直しと、旧名を参照する文書（README・CONTEXT.md・iterate-review・グローバルの codex 起用ルール）の更新が必要になる。
- CONTEXT.md から「輸送路」を削除し（TUI / CLI の対比が消滅）、「ハーネス」「裁定スコープ」「指揮者裁定」を追加、「奏者」「賢者」をロール名として再定義する。
- 承認ダイアログの裁定は指揮者（Claude 本体）の責務として常在化する。自動裁定の無いハーネスへの書き込み配役では裁定回数が増えるが、これは制限ではなくコストとして受け入れる。
