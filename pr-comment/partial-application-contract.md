# publish-polish 部分適用契約（正本）

pr-comment / pr-recheck が publish-polish を投稿文面の整形に部分適用するときの共通規定。
両スキルはこのファイルを参照する。各スキル固有の三点宣言（想定読者・配布形態・約束するもの）・
適用要点・保護対象の列挙は各 SKILL.md 側にあり、本契約には含まれない。

## publish-polish の解決手順

次の順で `publish-polish/SKILL.md` を探して Read する — (1) 参照するスキルの隣
（`../publish-polish/SKILL.md`）、(2) 実行エージェントのスキルディレクトリのプロジェクト側 →
グローバル側。どこにも無ければ処理を開始せず中止し、導入手順
（`npx skills add tmstack-io/agent-skills --skill publish-polish`）を案内する
（未整形の内部語混じり文面で投稿・返信する縮退はしない）。

## 契約

解決した publish-polish の**判定基準（削除候補のカテゴリ判定）と磨き込み基準のみ**を文面に適用する
（磨き込み基準は publish-polish 側では `--style` 指定時限定だが、部分適用では常に適用する）。

- publish-polish の「フロー」（対象列挙・提案レポート・承認・ファイル書き換え）は既存ファイルの
  書き換え用なので**実行しない**。フロー冒頭の「公開の姿の確認」のユーザーへの質問も行わず、
  適用するスキル側が**想定読者・配布形態・約束するもの**の三点を宣言して代える。
- **漏えいの疑いは投稿を保留する**: publish-polish の「要対応」区分（クライアント名・内部 URL・
  認証情報など漏えいの疑いがある記述）に相当する内容を文面に検出したら、**書き換えず**当該分の
  投稿を保留する。該当箇所と疑いの理由を示し、「修正して投稿する」「見送る」の二択を空行区切り・
  番号付きの散文で本文に提示し（各選択肢は採用後に何が起きるかが再読なしに分かる完結した文で
  書く）、ツールを呼ばずターンを終了して回答を待つ。「修正して投稿する」が選ばれた場合は、
  書き換え後の文面を before→after で提示して承認を得てから投稿対象に戻す。
- **保護対象は一字一句保持する**（何が保護対象かは適用するスキル側が列挙する）。
- **実体を変えない**: 主張・判定・根拠・条件・例外・推奨の数と強度を増減させない。
  publish-polish は視点の変換であり、内容の発明ではない。
- **各投稿を単体で成立させる**: 他の投稿や「上記の指摘」への参照を書かない
  （読者は別々の行で読む）。
