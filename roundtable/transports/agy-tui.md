# agy（Antigravity）TUI 輸送路 — 固有差分（議長裁定）

agy の対話ハーネスを賢者ペインで起用するときのハーネス固有差分。共通手順の正本は [../tui-protocol.md](../tui-protocol.md)（ペイン操作は `mux.sh` 経由）。agy には自動裁定機構（codex の `auto_review` / cursor-agent の `--auto-review` 相当）が無いため、**書き込み・シェル実行の承認は議長が裁定する**のが本ハーネス最大の固有差分である。

## 起動

`mux.sh run` に渡す起動コマンド:

```sh
cd '<プロジェクトルート>' && agy
```

- agy には cwd 指定オプションが無い（`--add-dir` はワークスペース追加であり cwd 固定ではない）ため、ペインのシェルで `cd` してから起動して tui-protocol の cwd 固定規定を満たす。
- モデルは当該席の `--model` 指定時のみ `--model <モデル>` を付加する。省略時はアカウントの既定（起動バナーに表示される。編成の宣言・question.md に記載する）。

## trust ダイアログ

cwd 単位で trust ダイアログが表示される。`mux.sh wait-output <ペインID> "Do you trust the contents" 15000` で確定待ちし、マッチしたら `mux.sh key <ペインID> Enter` のみで通過する（選択リスト形式で既定選択が「Yes, I trust this folder」のため）。trust 記録の永続性は未検証のため、起動のたびに確定待ちを付けたままにする（タイムアウト＝ダイアログなしは正常分岐）。

## エージェント検知と受理判定

- エージェント名 `agy`。**`agent_session` は null のことがある**（実測）— 受理完了の判定に `agent_session` は使わず、working 遷移＋（未遷移時は）tui-protocol 手順3の二分で判定する。

## 権限モデルと議長裁定

trust 通過後、**読み取りは無確認で実行される**（`● Read(...)` がペインに表示される。調査可）。**書き込みとシェル実行は承認ダイアログ**で停止し、その間エージェント状態は **`blocked`** と報告される（実測）。裁定は tui-protocol の「応答の受け取り」の安全網発火時三分類の blocked 分岐として行い、基準は次の二値:

- **ファイル作成/編集のダイアログ**（実測文言: `Allow creation of this file?` ＋ `1. Yes / 2. No` の番号選択）: 対象パスが議事録ディレクトリ内 → `mux.sh send <ペインID> "1"` ＋ `mux.sh key <ペインID> Enter` で許可。外 → `"2"` ＋ Enter で拒否し、書き込み規律への違反として失敗規律へ。
- **シェル実行のダイアログ**（実測文言: `Do you want to proceed?` ＋ `1. Yes / 2. 会話内 always allow / 3. 永続 allow / 4. No`）: コマンドが通信規約の push（`mux.sh send` / `key`。旧実測では herdr 直接コマンド）→ `"1"` ＋ Enter で許可。それ以外のコマンド → `"4"` ＋ Enter で拒否し失敗規律へ。ラウンド数の多い合議では、push の2回目以降に `"2"`（**会話内でのみ** always allow）を選んでよい。`"3"`（設定への永続化）は選ばない。

同一ラウンドで複数回発火しうる（実測: 回答ファイルの作成1回＋push 1回）。賢者自身による push は**毎回シェル実行の承認ダイアログで停止する**（実測）— 裁定で許可すると届く。pull 安全網での回収を必須とし、push はあれば早いという扱いにする。

## 検証記録

2026-07-30 実測（検証＋合議1件の実運用）: trust ダイアログの表示と Enter（既定選択 Yes）通過 / エージェント検知（`agy`・status。`agent_session` は null）/ 承認ダイアログ表示中の `blocked` 報告（pull 安全網が発火し分類できる）/ 読み取り・ウェブ検索の無確認実行とツール活動表示 / ファイル作成ダイアログの裁定（`1` 許可・`2` 拒否とも実効）/ push のシェル実行ダイアログ（`1` 許可で到達）/ headless（`agy -p`）は全ツール権限が自動拒否される（本スキルが TUI 専用である背景の一つ）。未検証: trust 記録の永続性 / 既存ファイル編集時のダイアログ文言。
