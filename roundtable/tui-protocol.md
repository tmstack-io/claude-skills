# tui-protocol.md — TUI 輸送路の共通原則と手順（正本)

賢者 CLI の対話ハーネスをペインで起用するときの、ハーネスによらない共通手順の正本。ハーネス固有の差分（起動コマンド・trust / 承認ダイアログ・裁定基準・実測記録）は `transports/<CLI名>-tui.md` が持ち、本書と矛盾する記述があれば transports 側（実測）を優先する。

原則は2つ。「**ペイロードはファイル、ペインは信号**」— 長文をペインに流し込まない。ブリーフ・回答はファイルで受け渡し、ペインには起動指示と通知だけを流す。「**待ちは確定待ち**」— 状態の完了を `sleep` で推測せず、`mux.sh wait-output` / `mux.sh agent-wait` による観測をもって次へ進む（入力ペーシングの短い `sleep` は状態待ちではない）。

ペイン操作はすべて同梱の **`mux.sh`**（マルチプレクサラッパー。サブコマンドの正本はスクリプトのヘッダ）を経由する。マルチプレクサの生コマンドを直接叩かない（バックエンド差の吸収とセッション毎のばらつき防止のため）。

## ペインの起動（賢者ごと・遅延）

ある賢者への最初の委譲が発生した時点で、その賢者のペインを起動する:

1. `mux.sh list` で **Claude ペイン ID**（`focused` が真の自ペイン）を取得する。以後、全ブリーフの通信規約に記載する。
2. `mux.sh split <対象ペインID> <方向>`（対象と方向は SKILL.md の「ペイン配置」規定）で新ペインを作り、出力されたペイン ID を得る。
3. `mux.sh run <ペインID> "<起動コマンド>"` でハーネスを起動する（起動コマンドは当該 transports の規定）。**賢者ハーネスの cwd はプロジェクトルートに固定する** — transports の起動コマンドにある `<プロジェクトルート>` は、議長セッションの作業対象プロジェクトの最上位ディレクトリ（`.git` / CLAUDE.md 等を持つルート）の絶対パスに議長が展開する。ペインのシェル cwd は分割元を継承するが、それに依存せず起動コマンド側の cwd 指定（cwd オプションまたは `cd`）を正とする（ブリーフの書き込み規律「議事録ディレクトリにのみ書く」の基準点を確定させるため）。
4. trust 等の初期ダイアログは当該 transports の規定で通過する（`mux.sh wait-output` で確定待ちし、`mux.sh send` / `mux.sh key` で応答する。確定待ちのタイムアウト＝ダイアログなしは正常分岐）。
5. `mux.sh agent-wait <ペインID> --until idle 60000` で入力待ちへの到達を確認する。
   - 起動直後はエージェント検知が未登録で `agent_not_found` により即失敗することがある（起動レース・実測）。失敗したら数秒おいて同じ確定待ちを1回だけ再実行する。
   - タイムアウトしたら `mux.sh read <ペインID>` で画面を読み、原因（予期せぬダイアログ・起動失敗等)を特定してから対処する。
6. ペイン ID を**席名→ペイン ID の対応表**（セッション内で保持）に記録する。

完了条件: 当該賢者のハーネスが入力待ち（idle）に達し、対応表に記録済み。

## タスクの委譲

1. ブリーフを議事録ディレクトリにファイルとして書く（ファイル名は SKILL.md の議事録規定。既存ファイルを上書きしない）。末尾に次のブロックを**一字一句そのままコピー**し、`<>` 内だけ実値に置換する（`<mux.sh>` は本スキルの `mux.sh` の絶対パス）:

   BEGIN-通信規約（ブリーフ末尾へコピー）
   - 完了したら: 本ブリーフに定めた回答ファイルを書き、次を実行する:
     `<mux.sh> send <ClaudeペインID> "[<席名>] done <回答ファイルパス>"` に続けて `<mux.sh> key <ClaudeペインID> Enter`
   - 不明点で作業を続けられないときは、作業を止めて次を実行する:
     `<mux.sh> send <ClaudeペインID> "[<席名>] question: <一行の質問>"` に続けて `<mux.sh> key <ClaudeペインID> Enter`
   - 上記コマンドが失敗した場合（Operation not permitted 等）: 回答ファイルはそのままに、同じ一行（`[<席名>] done <回答ファイルパス>` または `[<席名>] question: <一行の質問>`）を最終メッセージとして出力して終了する
   - git のコミット・stash・ブランチ作成はしない。変更は作業ツリーに残す。
   END-通信規約

2. 送信から受理の確定待ちまでを単一の Bash 実行で回す。ペインへ送るのは起動指示の一行だけで、テキストと Enter は別コマンドに分けて間を置く（同一バーストで届いた Enter はペースト処理に吸収される）:

   ```sh
   <mux.sh> send "$PANE" "<ブリーフ絶対パス> を読んで実行せよ" \
     && sleep 1 && <mux.sh> key "$PANE" Enter \
     && <mux.sh> agent-wait "$PANE" --until working 15000
   ```

   受理完了の条件: working への遷移（終了コード 0）に加え、応答 JSON に `agent_session` が含まれていること。ただし **`agent_session` を報告しないハーネスがある**（当該 transports に明示。その場合は working 遷移のみで手順3へ）。working でも `agent_session` が期待されるのに無い場合は、TUI 初期化中の描画を working と誤検知した空振り（送ったテキストは破棄済み）とみなし、受理としない。
3. 受理完了にならなければ `mux.sh read "$PANE" --lines 40` で入力欄を見て二分する（TUI 初期化直後の Enter 吸収は全ハーネス共通の前提）:
   - 指示テキストが入力欄に残っている → Enter のみ再送する
   - 入力欄が空 → 手順 2 からやり直す（idle は入力受付可能より先に報告されることがあり、初期化中に送ったテキストは丸ごと捨てられる）

   再送・やり直しは当該賢者につき合計 2 回まで。それでも受理完了にならなければ、SKILL.md の失敗規律に従い円卓を停止する（`mux.sh read` の内容を原因分析に添える）。
4. **pull 安全網**を賢者ごとに仕掛ける: `mux.sh agent-wait "$PANE" 1800000` を Bash の `run_in_background` で起動する（`--until` 無し = idle / done / blocked のいずれかで発火。ハーネスは完了後 idle に戻るだけで done を報告しないことがあり、`--until done` に絞ると完了を取り逃がす）。安全網は手順 2 の受理完了の確認後に張る（エージェント状態は画面からの推定であり、受理前の無活動ペインは done と誤検知され即発火する）。

完了条件: 委譲した全賢者について、受理完了の確認と安全網の起動が済んでいる。

## 応答の受け取り

push の `[<席名>]` で発信元を特定してから処理する:

- **`[<席名>] done <パス>`** が届いたら回答ファイルを読む。読まずに次工程へ進まない。
- **`[<席名>] question: ...`** が届いたら、回答を当該ペインへ `mux.sh send` ＋ `mux.sh key Enter` で送る。補足が長くなる場合はファイルに書いてパスを送る。
- **安全網が先に発火**したら `mux.sh read "$PANE" --scrollback --lines 60` で画面を読み、**三分類**する:
  - **承認ダイアログで停止（blocked）** → 当該 transports の裁定基準で許可 / 拒否を送信し、安全網を張り直す（同一ラウンドで複数回発火しうる）。対象パス・コマンドが表示で切れている場合は読み直して確認してから裁定する（対象不明のまま許可しない）。
  - **done / idle なのに push が無い** → 回答ファイルの有無と画面内容から結果を直接回収する（push 漏れは回収漏れであり、失敗規律の「失敗」に数えない。回答本文がペインにしかない場合は議長が本文のみを回答ファイルへ転記する）。
  - **まだ作業中（working）** → 安全網を張り直して待機を延長する。延長は賢者ごとに1回まで。2回目の発火はユーザーに相談する。

完了条件: 委譲した全賢者について、回答ファイル（または直接回収した結果）を読み終えている。

## ペイン ID の揮発性

ペイン ID はペインの増減で振り直される。増減操作（起動・クローズ）を行ったら、直後に `mux.sh list` を取って対応表を更新する。`mux.sh close` / `run` / `send`（`key` と一体の送信は一式で1回）の直前は `mux.sh list` で ID を取り直す — 複数ペインでは、古い ID への送信が**別の賢者**を撃つ事故になる。取り直しで当該賢者のペインを特定できないときは、送信せずユーザーに確認する。

## クローズ

ペインは**作業時のみの窓**である。次の3条件が当該賢者について揃ったら閉じてよい: (1) 未回収の委譲・次ラウンドの委譲が無い (2) 未回収の push が無い (3) 当該賢者の pull 安全網が発火済みまたは停止済み。クローズ期限は SKILL.md の「後始末」規定（verdict 提示後・確認なし全クローズ）に従う。`mux.sh list` で ID を取り直してから `mux.sh close` し、対応表から除く。次ラウンドの委譲が確定している間は閉じずに同一ペインへ追送する（ペインの文脈保持が本輸送路の価値であり、閉じれば失われる）。

完了条件: 閉じたペインが `mux.sh list` に存在しないことを確認した。
